# torch/torchvision are intentionally NOT pinned here, same reasoning as onnxruntime-gpu in the ONNX server's
# requirements.txt: setup_diffusion.sh installs the cu12x wheel matching the detected driver, from
# download.pytorch.org's own index rather than PyPI, so pinning a version here would just get overridden anyway.
#
# triton IS constrained, unlike torch/torchvision above, for the opposite reason: left unpinned, transformers/
# accelerate pull in whatever's newest on PyPI (seen: 3.9.0), which in turn depends on NVIDIA's new unsuffixed
# "nvidia-cublas" package — a *different* package from the "nvidia-cublas-cuNN" one torch's own install already
# satisfies, built for the CUDA 13 generation, and several hundred MB by itself. None of these backends use
# torch.compile or custom Triton kernels, so there's no upside to the newer version. Not pinned to an exact
# version (torch itself is unpinned above — whichever release the cu128 index currently serves — and different
# torch releases want different exact triton builds), just capped below the release that introduced the CUDA-13
# dependency, so pip still picks whatever triton that resolved torch version actually wants.
